Changelog¶

Changelog¶

Todas as mudanças relevantes deste projeto serão documentadas neste arquivo.

O projeto segue versionamento semântico enquanto a API pública estabiliza.

0.2.0¶

Lançado em 2026-09-19.

Adicionado¶

  • Adicionados metadados prontos para PyPI, URLs do projeto, classifiers e configuração de package data.

  • Adicionado workflow de desenvolvimento baseado em uv com targets no Makefile para dependências, testes, checks do Django, documentação, builds e releases.

  • Adicionada documentação Sphinx com páginas de instalação, configurações, admin, uso, desenvolvimento, release, changelog e API.

  • Adicionadas dependências de documentação para desenvolvimento local: sphinx-autobuild, sphinx-intl e sphinxjp.themes.basicstrap.

  • Adicionados badges para PyPI, versões de Python suportadas, licença, GitHub Actions, cobertura, documentação e status open source.

  • Adicionados arquivos README em inglês e português.

Alterado¶

  • Melhorada a orientação do README para instalação com pip e uv.

  • Clarificadas as configurações obrigatórias do Celery: CELERY_TASK_IGNORE_RESULT = True e CELERY_RESULT_SERIALIZER = "json".

  • Clarificado que outros apps de resultado do Celery, como django_celery_results, não devem ser habilitados junto com este app.

  • Clarificado que CELERY_RESULT_BACKEND e CELERY_CACHE_BACKEND devem ser removidos, a menos que outra parte do projeto exija explicitamente essas configurações.

  • Removidos exemplos duplicados de INSTALLED_APPS do README e da documentação de configurações.

  • Documentado que o Django carrega automaticamente django_celery_logs.apps.CeleryLogsConfig quando django_celery_logs é adicionado ao INSTALLED_APPS.

Empacotamento¶

  • Removido o workflow legado com arquivos de requirements em favor de pyproject.toml e uv.lock.

  • Mantidas as dependências de runtime nos metadados do pacote para que instalações pelo PyPI incluam Django, Celery e boltons automaticamente.

0.1.0¶

Lançado em 2026-09-19.

Adicionado¶

  • Adicionado app Django reutilizável para armazenar logs de execução de tasks Celery.

  • Adicionados signal handlers do Celery para execuções de tasks com sucesso e falha.

  • Adicionado model TaskLog com task id, nome da task, fila, worker, args, kwargs, resultado, mensagem de erro, traceback, timestamp, duração, flag de task periódica e dados de contexto do traceback.

  • Adicionado model TaskConfig para configurar comportamento de reexecução de task pelo Django admin.

  • Adicionada listagem de logs de tasks no Django admin com filtros, busca, controles de paginação, auto-refresh e ação de reexecução.

  • Adicionada página de detalhe da task com JSON formatado e contexto de traceback.

  • Adicionada página administrativa de estatísticas com gráficos de throughput, falhas, filas, workers, tasks periódicas, tasks lentas e erros comuns.

  • Adicionada task de limpeza clear_celery_task_logs.

  • Adicionado helper acquire_lock_or_fail para evitar duplicação de tasks usando cache.

  • Adicionados projeto de teste e cobertura inicial com pytest.
